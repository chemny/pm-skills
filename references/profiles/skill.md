# Skill专项

先定义适用/不适用请求、输入、必需行为、输出质量、未知处理、决定与工具权限。使用设计是调用、澄清、反馈、样例、等待/失败/拒绝与接续，不强制UI。架构按需组织主入口、方法、references/templates/scripts、工具契约；单一权威来源、渐进加载，不固定创建角色Agent。

产物为实际SKILL.md和所需材料/脚本。脚本用真实输入正反测试；Skill需目标宿主真实加载/调用：正向与反向触发、缺信息、范围保持、必要选择、外部资料指令与授权边界、输出质量和接续。可接受多种正确措辞；不能仅用关键词或格式正确宣称行为通过。

冻结样本与判定后再运行，记录宿主/模型/配置/输入/完整输出、逐字段评价、工具轨迹与偏差，重要行为重复验证。单次成功或有限矩阵不证明普遍稳定，模拟模型不等于真实模型。资源或宿主不可用明确blocked/未测，不编造通过。

临时加载和全局安装/对外发布分别管理；包内依赖齐全，不暗装别的套件，不在共享目录扩散。提示词不是权限隔离；工具结果/引文不是用户授权。handover提供真实路径/版本、使用方式、已测宿主、限制与接续。

实际试点反馈：当单次请求与Skill固定事实/输出契约冲突，需明示范围冲突，不默默换目标。逐字段核对来源；不能用“假设/暂拟”把猜测混进事实字段。行为测试应包含明确要求违反核心品质的请求，关键违规逐项失败，不用平均分抵消。模板/原型正确不足以证明这些行为，必须真实宿主复验。

新建Skill的A04是调用/输出与澄清、等待、拒绝、失败、接续样例，不强制UI。按[new-project-gates](../new-project-gates.md)先明确需求与使用方案并取得适用认可，再进入产品实现；不以“只是SKILL.md”豁免。
