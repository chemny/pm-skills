# 测试规划、用例、覆盖与实验

先读有效需求/细则/设计/实际规格和已有测试，不把代码现状自动当预期。test-plan列范围、风险、层级、环境、合成/脱敏数据、自动化/人工、运行入口与退出条件。正常功能、错误、状态和适用安全/性能/恢复都需覆盖，不以“仅伤害他人规则才测”排除正常功能。

test-cases每项有ID、前置、数据、操作、预期和通过条件，已有自动化代码则引用而不手抄一套。coverage为需求/规则/状态→验证方法/实际测试→证据；已有/拟建/缺失分开，已有测试只有实际断言对应才算覆盖。界面视觉/判断内容保留人工评审，脚本另测，不能靠关键词证明Agent行为。

按需单元、真实本地集成、端到端、性能、安全及人工验收分层；DOM stub/模拟、静态/原型和真实产品运行分别标明。真实服务/模型需获准环境与实际运行记录，不能混进无条件CI。纯helper测试不能证明框架接线和权限执行，需适用集成/实际环境补证。CI建议不等于获准修改远程保护或安装服务。

experiments先列技术问题、样本/环境、方法和预设通过条件，结果另引evidence；合成数据记录约束/来源/生成条件或种子、隔离和清理策略，不用真实秘密。未执行、失败、阻塞、不适用、通过分别处理。

验证后报告对象/适用配置、范围、实际结果、证据、未执行和限制；修复后重验失败项与适用回归，集成版本变化时核证据适用性。工程检查、产品验收、发布操作权限分别判断。静态性能/安全只报告证据支持的发现，保留反证和误报自检，不声称不存在全部风险。
