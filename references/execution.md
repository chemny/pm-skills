# 实施、评审、修复与集成

主Agent持续负责目标、授权、任务状态、集成和最终验收。任务包含有效输入版本、需求/设计、目标产物、依赖、修改范围、共享接口、验证数据/方法/预期、DoD和集成责任；不要把未定产品行为转给执行者猜。

1. 先核实际工作区和工具，再核当前任务八项就绪条件。按state-and-evidence的check_state读取ready_tasks与相关诊断；脚本是形式检查，依据/决定/设计语义与实际许可仍需核查。只在已获准范围动手。小任务可用宿主工具，但必须有本轮具体任务check_task_ready的can_start、动作类型/范围与实际轨迹，不能借“小任务”绕过。
2. 用实际CLI/MCP/专用接口实现并在修改范围内核差异。执行者可以是主Agent、普通工具或获准的有界子任务，不依赖指定套件、固定岗位或永久后台。
3. 对当前对象做单元/适用集成/使用检查和评审，保留失败批次。缺陷用issues记录实际/预期、复现、影响、修复版本和复验。修复后重跑失败项与受影响回归；代码/配置/接口变化需核旧证据适用性。
4. 集成方核返回成果、实际测试和范围，不盲信执行者摘要；集成后再确认适用结果。done要有当前对象、通过的必要证据、问题处置和一致记录；done不是已发布。

## 串并行和失败

依赖完成且输入/接口稳定、修改边界隔离时，独立任务可并行；有冲突先协调或串行，不能同时改同一权威来源。可用同一主Agent并行调用独立本地工具，不要求多Agent；实际子Agent须有相应授权与宿主支持。派发结果不是用户授权，主Agent复核并负责集成。

产品预期改变先记录范围决定并更新受影响要求；纯实现缺陷保持原预期；接口/环境改变据依赖链标设计、任务和证据待重核。受影响done重新打开到planned/blocked并保留旧证据，不强制所有无关工作重做。runtime.plan_impact只计算影响，不替用户批准变化。

区分规格缺口、实现缺陷、环境/工具故障和未知副作用。相同失败无新证据不反复重跑；调整方法/条件或准确阻塞，资源/重试按实际授权约定。不可确定外部动作结果先查，不重发消息/付款/发布。缺工具不暗装，缺模型或环境不伪造通过。进度从唯一state给用户：具体完成、正在做、阻塞、需决定和下一步；无需决定的就绪任务继续，真正选择保持等待。

所有实施先按实际动作分类。任何探针编写/编译/运行、本地模型调用都受experiment准入；合成与本地不豁免。实施例外只覆盖已登记scope、命令、次数、样本和副作用。原型模拟代码不等于正式实现，不允许暗接真实采集/模型/业务存储。

本地命令执行用task绑定的record_evidence/runtime.record，不直接调内部_record_command；MCP/API/浏览器等宿主工具保留渠道原始响应和调用标识，并满足state-and-evidence的任务绑定证据契约，不强制伪造进程日志。任何编译、模型或真实能力调用前做具体任务开工检查，状态/版本变更重新核；直接工具没有前置检查与可追溯任务时，行为验收失败。

查找已有程序/组件和定位兼容性问题时按[local-capability-diagnosis](local-capability-diagnosis.md)落实搜索范围、支持证据和失败阶段；未知不等于不存在。完成前调用state-and-evidence的complete_task接口复用已有原始证据并核对任务/运行绑定；历史补录不能代替缺失的事前准入，不以重跑掩盖原偏差。

## 当前请求与授权来源的执行绑定

开工核查要区分有效的既有许可与本轮新增/细化的许可。当前请求首次覆盖具体实验或操作时，先保存其真实原话，登记input及task.input_ids，将相应决定source和approval_ref绑定该快照，再执行check_task_ready与受管调用。context.authority可保留真实的总体授权，但不能用它代替新操作所需的具体来源。仅落盘current-request一类文件、未进入实际引用链，不足以支持后续接手判断。

有效旧许可已明确覆盖当前动作时直接复用，不强制重写或重复询问。运行已经发生后发现绑定缺口，保留原始事前记录和技术观察，另记流程偏差；不能事后伪造当时已绑定，也不为补索引自动重跑。


具体任务检查返回can_start=false后，停止该任务的产物/脚本编辑与实际调用，不能先修一行检查器再补恢复记录。若仅是已获授权的任务状态或记录问题，先如实恢复控制记录（必要时登记独立记录维护任务），重新核当前具体任务；得到新的can_start=true后才编辑或执行。若缺少真实决定、操作许可或必要输入，继续保持阻断，不能通过改状态制造满足条件。控制记录恢复不等于业务动作已获准，也不追认先前已经发生的偏差。

命令的输出重定向、检查回执、临时文件和辅助脚本也属于写入。执行前核对这些路径均在本任务实际允许范围内；只读检查使用了重定向时不能称为零写入。不得先在范围外写入，再移动到允许目录来代替事前范围核验；发现偏差须保留事实并阻断该项通过，修正后验证。此要求针对当前任务产生的项目文件，不声称可限制宿主工具全部系统级缓存或副作用。
