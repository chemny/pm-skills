# 已有能力查找与兼容性诊断

在寻找可复用的工具、模型、应用内能力，或解释“文件存在但不能运行”时读取。只读发现不授权安装、启动模型、录音或改配置；实际调用仍走具体任务准入。

## 先确定问题和预算，再查可复用证据

产品方案按需求、质量和交付成本评价；实际实验可以为节省磁盘、时间和安装影响复用已有组件。不得因本机恰好装了某组件就把它升为产品默认。沿用已确认的禁止下载/安装、样本范围、运行次数等限制，不重复索要同一许可。需要扩大范围时才请用户决定。

先读项目、历史运行索引和先前失败，按其路径线索核实当前文件与版本。历史报告中成功不代表当前运行环境仍存在；重跑也不是读取历史报告的默认动作。

按相关性逐层查：当前项目与历史资料 → 常用命令/环境 → 已有应用的公开CLI及内置组件 → 相关开发目录与缓存。选定的根目录、关键词/别名、深度/数量或时间上限和未查范围形成搜索记录；无需默认扫描全盘。相互独立的只读查找可以批量执行。

可用 `scripts/local_capabilities.py --root <目录> --name <文件名或相对路径glob>` 作有界只读查找，根目录与名称可重复指定。它包含隐藏文件、不跟随符号链接、不执行候选，输出覆盖/截断/缺失/错误信息。目录上限、条目预算、权限错误、跳过链接或外部输出截断均属于覆盖限制。只能报告“在这些范围未找到”，不能推出“本机不存在”。必要时按线索调整根目录，而非反复跑同一个无效查询。

区分四种发现：仅见代码/文档、见模型或数据文件、见可执行入口、已在指定输入上运行验证。文件名、执行位、应用自带组件或README宣称均不足以证明能调用。不要把库文件当独立程序启动，也不要为试探启动可能录音、联网更新或改变配置的GUI应用；先核公开参数/入口及副作用。

## 执行前核对兼容组合

核对模型/数据的家族与版本、转换来源、格式/量化、运行时及其支持证据、输入格式与参数。相同容器格式不代表内部架构兼容；GPU后端名称也不等于采用某个特定模型框架。`assess_compatibility` 可比对已查证的家族、格式、输入声明；匹配只返回 declared-compatible-not-run，信息不全则blocked，不推断质量或下载必要性。

按失败发生阶段定位：文件发现/校验 → 运行时加载 → 输入解析 → 推理/处理 → 输出解析 → 质量评价。加载失败时先查格式/架构/版本组合，不能推断模型识别质量差。输入错误先核采样率、编码或契约，输出字段错误先核接口版本。没有文件损坏证据或明确格式替换需求，不建议重新下载权重。

优先采用已有兼容入口、在工作副本转换小样本等符合现有授权的最小修复。确需补齐组件时先列来源/版本、下载大小、安装及临时/缓存/峰值占用、目标位置和可撤回方式；实数与估算分开，未知明确标出。没有下载/安装授权就停在方案。不要以“修环境”为由突破原有停止条件。

## 运行和结论

授权明确且兼容条件具备后，以最小的已授权样本通过任务绑定记录器执行；不让样本去向、自动下载或可选云模式成为隐式行为。记录确切入口与组件身份、原始输出、退出码、耗时口径和判定。脚本输出中的速度倍数与处理时间比要按其实际定义解释。

只解锁实际证明的能力：能加载/能输出、目标样本质量、长时稳定、集成和产品验收分别表达。修复失败结论时保留旧记录并追加更正来源。历史未登记调用按 recovery 补录，不能为让状态通过而伪造原始日志、前置检查或事前授权。
